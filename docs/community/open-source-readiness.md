# Open Source Readiness

目标是让外部参与者能理解、运行、验证和共同改进系统，同时不把真实用户人格变成社区资产。

## 公开前必须完成

- [ ] 选择并记录代码、SDK、文档许可证；
- [ ] 完成商标政策；
- [ ] 填写真实 Maintainer 与安全联系方式；
- [ ] 启用 Private Vulnerability Reporting；
- [ ] 建立 DCO 或 CLA 决策；
- [ ] 所有 Fixture 均为合成数据；
- [ ] 运行 Secret、PII 和大文件扫描；
- [ ] 英文 README 与最小英文文档；
- [ ] CI 在全新环境通过；
- [ ] 至少一个五分钟安全演示；
- [ ] 已知限制、数据边界和成熟度醒目标注。

## 许可证待决

候选方案：

1. 全部 Apache-2.0：生态采用阻力最低，适合作为行业基础设施。
2. 服务端 AGPL-3.0-or-later，协议与 SDK Apache-2.0，文档 CC-BY-4.0：鼓励托管修改回馈，同时保持生态接口宽松。

这是商业模式与社区契约，不在没有明确决定时自动生成 LICENSE。接受外部贡献前必须通过 ADR 锁定。

## 公共/私有边界

可以公开源码、Schema、ADR、合成任务、聚合 Benchmark 和脱敏故障分类。

永不公开：

- 原始语音、聊天、浏览、Self Model 与 Embedding；
- 凭据、账号标识、真实草稿 ID 与 Receipt；
- 可重建个人经历的完整 Prompt 或 Trace；
- 未修复漏洞的利用细节。

生产日志默认记录引用、版本、Hash 与结果，不记录正文。维护者身份不自动赋予用户数据访问权。

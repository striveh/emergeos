# Five-Outcome Charter

EmergeOS 同时服务五个长期结果：

1. 掌握 AI Coding 时代的工程经验、技能与判断；
2. 掌握 AI Agent 的原理、实现、评测与生产运维；
3. 做成真实可用、可运营、可演进的生产级产品；
4. 形成可信、可追问的面试作品与职业竞争力；
5. 找到可重复的付费价值，最终形成可观收入。

这五项不是五个互相争夺时间的副项目。产品是真实问题场，学习提升解决问题的能力，
工程证据沉淀为职业资产，用户价值和分发转化为商业结果。

```text
真实用户问题
  → 生产级解决
  → 原理与故障被掌握
  → 可验证作品与公开叙事
  → 用户留存、付费与增长
  → 更多真实问题
```

## 优先级

发生冲突时，按以下顺序决策：

1. 用户安全、数据主权和行动可逆性；
2. 被验证的用户结果和付费信号；
3. 生产正确性、可恢复性与可维护性；
4. 可迁移的原理与工程能力；
5. 可展示的职业证据；
6. 新框架、新名词和表面完成度。

面试素材必须来自真实工作，学习必须通过解释、实现和排错证明，收入必须来自真实用户。
不为了简历堆技术，不为了“自我进化”制造不可控行为，也不把 GitHub Star 当作市场验证。

## 五条证据轨道

| 轨道 | 要回答的问题 | 有效证据 | 无效替代品 |
|---|---|---|---|
| AI Coding | 能否让 Agent 提速且仍由人理解、审查和负责？ | Red/Green 记录、Diff 审查、故障复现、复盘、周期时间 | 生成代码行数、Prompt 数量 |
| AI Agent | 能否解释并实现模型、工具、上下文、状态、运行时、评测和治理？ | 机制笔记、对照实验、Trace、故障注入、可替换 Adapter | 只会调用框架 Demo |
| Production | 用户能否稳定、安全地完成 Thought-to-Outcome？ | SLO、集成测试、恢复演练、审计、部署、真实 Receipt | 本地截图、一次成功调用 |
| Career | 雇主和同行为何相信这些能力？ | 五分钟 Demo、ADR、Benchmark、故障故事、连续追问 | 虚构指标、技术名词、背稿 |
| Business | 用户为何重复使用、付费并推荐？ | 用户复用、付费试点、留存、收入和单位经济 | 问卷意向、Star、宏大愿景 |

## 防偏航规则

### 每个任务

开始前至少写明：

- 一个用户或系统结果；
- 一个主要风险；
- 一个本次要掌握的原理；
- 可执行的完成条件。

小任务不必强行产生商业或面试材料。

### 每个 Roadmap Stage / Release Gate

必须同时留下：

- **AI Coding Receipt**：任务切片、委派、审查、调试或效率改进证据；
- **Agent Engineering Receipt**：能解释、实现、打破并比较 Agent 机制的证据；
- **Product/Production Receipt**：用户结果以及测试、恢复、安全或运维证据；
- **Career Receipt**：可演示、可追问、无夸大的项目材料；
- **Business Receipt**：用户访谈、复用、承诺、付费或明确拒绝原因。

缺少任何一项时，里程碑可以标记为工程完成，但不能标记为项目完成。
普通工程 Slice 只记录与本次变化相关的 Receipt，可以写 `N/A`，不为凑齐五项而伪造证据。

### 每周与每月

每周做 15 分钟 Pulse，每月使用
[Five-Outcome Scorecard](../operations/five-outcome-scorecard.md) 深度回顾：

- 是否连续只写基础设施而没有用户结果；
- 是否大量使用 Codex 却无法解释自己的系统；
- 是否只学习概念而没有故障与实现证据；
- 是否只发布内容却没有留存或付费信号；
- 是否为了赶进度降低权限、隐私和恢复标准。

连续 7 天没有用户接触或连续两个基础设施切片没有用户/市场证据时，冻结新增基础设施；
月度回顾连续两次失衡时，下一周期必须优先补最弱轨道。

## 人与 Codex 的责任边界

Codex 可以搜索、实现、测试、审查和并行探索，但不能替代以下责任：

- 用户决定问题、价值、风险容忍度与最终发布；
- 主 Agent 维护任务真相、架构一致性、验证执行和证据汇总；
- 人类所有者承担风险，决定里程碑最终接受与 go/no-go；
- 人必须能解释关键状态机、数据边界、失败窗口和技术取舍；
- Subagent 结果是待验证提案，不是事实；
- 只有测试、运行回执、用户行为和付费才是结果证据。

## 商业原则

“赚大钱”不是一个可验收的功能，但可以拆成可验证的增长链：

```text
高频痛点
→ 相对现状有可测优势的闭环
→ 重复使用
→ 愿意付费
→ 可复制获客
→ 达到预注册的留存与贡献毛利 Gate
```

产品首先服务一个清晰的滩头用户群。创始人自用可以发现问题，不能证明市场。
在建设多租户、计费和大规模 Connector 前，必须获得外部用户的重复使用和至少一个
真实付费试点。定价通过承诺和付款测试，不通过问卷里的“我可能会买”决定。
